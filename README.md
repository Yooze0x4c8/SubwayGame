# SUBWAY

앞사람이 도착한 역에서 노선을 이어 가는 실시간 멀티플레이 지하철 게임입니다. 제한 시간 안에 현재 노선과 연결되는 역을 입력하고, 환승과 새 노선 개척으로 점수를 얻습니다.

## 주요 기능

- 2~8인 실시간 멀티플레이와 6자리 초대 코드
- 공개·비공개 방, 비밀번호, 준비 상태와 방장 설정
- 게임 시작 시 무작위로 정해져 마지막 라운드까지 유지되는 턴 순서
- 일반 지하철 모드와 전국 KTX·SRT를 연결하는 고속철도 확장 모드
- 라운드 시간과 개인 턴 시간을 분리한 이중 타이머
- 환승, 새 노선, 긴 역명, 답변 속도를 반영한 점수 계산
- 관전, 실시간 채팅, 연결 복구와 방장 위임
- 라운드별 이동 경로와 게임 종료 후 경로 리플레이
- 모바일 소프트 키보드를 고려한 반응형 UI
- 서버 권위형 판정과 재현 가능한 게임 엔진 테스트

## 게임 방법

1. 닉네임을 입력하고 방을 만들거나 공개 방 또는 초대 코드로 참가합니다.
2. 방장이 라운드 수, 제한 시간, 게임 모드와 노선 난이도를 설정합니다.
3. 게임이 시작되면 참가자 순서가 무작위로 한 번 정해집니다. 이 순서는 게임이 끝날 때까지 유지됩니다.
4. 자신의 차례에 현재 노선과 연결되는 역 이름을 입력합니다.
5. 현재 역이 환승역이면 해당 역의 다른 노선으로 갈아탈 수 있습니다.
6. 한 라운드에서 이미 나온 역은 다시 사용할 수 없습니다.
7. 오답은 제한 시간 안에 다시 입력할 수 있지만, 턴 시간이 끝나면 해당 라운드가 즉시 종료됩니다.
8. 모든 라운드가 끝났을 때 누적 점수가 가장 높은 참가자가 승리합니다.

고속철도 확장 모드는 수도권에서 시작해 서울·용산·수서 등의 역에서 KTX·SRT로 환승하고, 도착한 지역에서 다시 도시철도로 이어 가는 방식입니다.

### 점수

| 항목 | 점수 |
| --- | ---: |
| 기본 정답 | +10 |
| 긴 역명 | 4글자부터 글자당 +2 |
| 환승 성공 | +15 |
| 새 노선 개척 | +20 |
| 빠른 답변 | 최대 +10 |

정답을 입력할 때마다 라운드 시간에 1초가 추가되며, 한 라운드에서 최대 30초까지 추가됩니다.

### 시간 초과 정산

| 대상 | 점수 |
| --- | ---: |
| 시간 초과 플레이어 | −10~50 |
| 직전 정답자 | +20 |
| 그 외 생존자 | +5 |

시간 초과 감점은 남은 라운드 시간에 비례합니다. 오답, 중복 역, 노선 불일치는 즉시 감점되지 않습니다.

## 기술 구성

- 클라이언트: React 18, TypeScript, Vite, Zustand
- 서버: Node.js, TypeScript, Socket.IO
- 테스트: Vitest, Testing Library, jsdom
- 배포: Docker, Fly.io 호환 설정
- 데이터: CSV 기반 역·노선 인덱스와 비트마스크 판정

## 프로젝트 구조

| 경로 | 역할 |
| --- | --- |
| `packages/client` | React 화면, 상태 저장소, Socket.IO 클라이언트 |
| `packages/server` | 방 관리, 실시간 통신, 게임 엔진, 정적 파일 서버 |
| `packages/shared` | 공용 타입, 프로토콜, 판정·점수·타이머 로직 |
| `config/balance.json` | 시간, 점수, 라운드 등 게임 밸런스 설정 |
| `data` | 정규화된 역·노선 데이터와 원본 참고 자료 |
| `tools` | 철도 데이터 생성·검증 도구 |

## 시작하기

### 요구 사항

- Node.js 22 이상
- npm

### 설치

```bash
git clone https://github.com/Yooze0x4c8/SubwayGame.git
cd SubwayGame
npm ci
```

### 개발 실행

먼저 공용 패키지와 서버를 빌드한 뒤 서버를 실행합니다.

```bash
npm run build
node packages/server/dist/index.js
```

다른 터미널에서 Vite 개발 서버를 실행합니다.

```bash
npm run dev --workspace=packages/client
```

- 클라이언트: `http://localhost:5173`
- 게임 서버: `http://localhost:3000`

클라이언트는 개발 환경에서 기본적으로 `http://localhost:3000`의 Socket.IO 서버에 연결합니다. 서버 TypeScript 코드를 수정했다면 다시 빌드하고 서버 프로세스를 재시작해야 합니다.

### 프로덕션 빌드 및 실행

```bash
npm run build
npm run build --workspace=packages/client
node packages/server/dist/index.js
```

프로덕션 서버는 빌드된 React 앱과 Socket.IO를 같은 포트에서 제공합니다. 기본 주소는 `http://localhost:3000`입니다.

## 검사

```bash
# 타입 검사
npm run typecheck

# 전체 테스트
npm test

# 테스트 감시 모드
npm run test:watch
```

테스트는 공용 판정·점수·타이머, 서버 게임 엔진·방·소켓 수명주기, 클라이언트 상태와 주요 화면을 포함합니다.

## 환경 변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 및 Socket.IO 서버 포트 |
| `STATIC_DIR` | `packages/client/dist` | 서버가 제공할 정적 클라이언트 빌드 경로 |
| `VITE_SERVER_URL` | `http://localhost:3000` | 개발 클라이언트가 연결할 게임 서버 주소 |
| `RENDER_EXTERNAL_URL` | 없음 | 설정 시 Render 환경에서 상태 확인용 자체 호출 활성화 |

서버 상태는 `GET /health`, 프로세스 수명 동안 수집된 플레이 지표는 `GET /metrics`에서 확인할 수 있습니다.

## Docker

```bash
docker build -t subway-game .
docker run --rm -p 3000:3000 subway-game
```

컨테이너가 시작되면 `http://localhost:3000`에서 게임에 접속할 수 있습니다.

## 데이터

현재 정규화된 데이터는 도시철도와 고속철도를 합쳐 989개 역, 48개 노선을 포함합니다.

- 수도권, 부산, 대구, 대전, 광주 도시철도
- KTX 7개 계통, SRT 5개 계통과 전국 고속철도역
- 출처와 기준일, 지역별 통계: [`data/meta.json`](data/meta.json)

데이터를 갱신할 때는 `tools`의 생성 도구와 서버 데이터 로더 테스트를 함께 확인해야 합니다.
